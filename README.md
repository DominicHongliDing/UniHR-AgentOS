# UniHR AgentOS

面向高校人事与行政经办人员的 AI 任务工作台。用自然语言发起任务，将政策查询、材料整理、Word / Excel 生成与人工复核接在一起。

[看交互展示](https://dominicspace.com/#unihr) · [典型任务](#经办人可以用它做什么) · [设计取舍](#几个关键的产品选择) · [本地启动](#本地启动) · [技术细节](docs/RUNTIME-DETAILS.md) · [关于作者](https://github.com/DominicHongliDing)

## 我为什么做这个项目

在国际医学院做行政、人事和国际交流相关工作时，我经常遇到一些很具体的琐事：查一条政策，要在不同文件里确认版本；做一批表格，要反复核对字段和公式；准备通知和会议材料，内容整理好以后，还要调整格式、附件和落款。

参与 AI 赋能业务流程优化、和经办人沟通之后，我更想解决的是这些工作之间的衔接。用户提出一个要求，往往要经过找资料、整理内容、处理文件和人工确认，才算真正办完。

UniHR 因此以“交付一项工作”为目标。经办人可以从一句话或一批材料开始，查看处理过程，核对依据，最后拿到可以修改和继续使用的文件。

## 经办人可以用它做什么

| 想完成的工作 | 工作台怎样帮助 | 用户拿到什么 |
|---|---|---|
| 查一项人事政策 | 结合当前问题检索原文，检查版本与适用范围 | 带出处的回答，方便回到原文件核对 |
| 整理岗位与候选人材料 | 按岗位要求比较材料，保留原文依据和待核实项 | 比较结果与 Excel 报告，供招聘人员复核 |
| 制作通知、会议材料或业务表格 | 先明确内容与格式，再调用文件工具生成和检查 | 可编辑的 Word / Excel 与检查结果 |
| 完成跨步骤的连续任务 | 拆解任务，保留中间结果，在需要时请求人工确认 | 可查看进度、继续修改的任务记录 |

## 一个任务如何完成

以“根据材料整理一份通知，并附上对应表格”为例，用户先提供材料与要求，系统确认需要生成的文件和关键约束；复杂任务先组织处理步骤，再分别准备内容、生成文件和检查结果。经办人核对依据、字段和格式，提出修改，最后自行决定正式使用与发送。

```mermaid
flowchart LR
    A[说明需求与提供材料] --> B[确认目标与处理步骤]
    B --> C[查资料并处理文件]
    C --> D[检查依据与交付物]
    D --> E[人工核对与确认]
    E --> F[下载或继续修改]
```

## 几个关键的产品选择

### 先定义用户要拿到什么

公文任务要交付可编辑文件，表格任务要检查数据和公式，政策问答要能找到原文。不同任务使用不同验收要求，生成一段流畅的回答只完成了其中一部分。

### 简单任务直接做，复杂任务保留计划

单项任务走短路径；跨文件、跨能力的工作按依赖组织步骤，保存中间产物。某一步需要返修时，可以针对该环节处理，用户也能理解当前进度和待确认事项。

### 重复工作沉淀方法，关键决定留给人

Skill 保存可复用的方法与约束，当前任务的材料单独管理。招聘录用、定薪与正式发送等事项保留人工确认，AI 提供整理、比较和文件处理的帮助。

## AI 技术在产品里起什么作用

| 能力 | 负责的工作 | 为什么需要它 |
|---|---|---|
| 大模型与任务识别 | 理解口语需求、连续追问和修改要求 | 经办人可以按自己的说法表达任务 |
| RAG 政策检索 | 找到相关条文，核对版本并关联引用 | 回答能回到原文，方便检查适用范围 |
| Agent 与任务编排 | 按需要组合政策、文档、表格等能力 | 一项工作可以跨越多个处理步骤 |
| 工具调用 | 实际读取材料、生成 Word / Excel | 用户最终能拿到文件 |
| 上下文与任务状态 | 保留目标、约束、中间结果和未完成事项 | 后续追问能接着已有工作继续 |
| 文件检查与受控返修 | 检查字段、结构、公式等要求，反馈到对应步骤 | 让交付物有明确的验收过程 |

这些机制共同构成 Agent 的运行支撑（Harness）。技术选型服务于文件交付、可核对性和人工控制，详细实现见[运行机制](docs/RUNTIME-DETAILS.md)和[系统设计](docs/ARCHITECTURE.md)。飞书机器人可接入同一套能力，方便在已有协作环境里发起任务。

## 本地启动

### 准备环境

- Windows 10/11，目前的一键脚本面向 Windows
- Python 3.11+
- Node.js 20+
- Docker Desktop
- 可用的阿里云百炼 / DashScope API Key

### 1. 下载并安装依赖

```powershell
git clone https://github.com/DominicHongliDing/UniHR-AgentOS.git
cd UniHR-AgentOS
.\setup.ps1
```

### 2. 配置模型

打开根目录的 `.env`：

```dotenv
UNIHR_BAILIAN_API_KEY=你的百炼APIKey
```

模型路由、Embedding、Rerank、本地数据库目录与 PostgreSQL Checkpointer 已提供默认配置。如果你的百炼账号不能使用某个默认模型，可以在同一文件中替换模型名称。

### 3. 启动

```powershell
.\start.ps1
```

浏览器会打开 [http://127.0.0.1:5180](http://127.0.0.1:5180)。

本地演示账号：

| 角色 | 用户名 | 密码 |
|---|---|---|
| 管理员 | `admin` | `UniHR@2026` |
| 普通 HR | `hr-user` | `UniHR@2026` |

这些账号仅用于本机演示。共享部署前，请在 `.env` 中修改账号密码和 `APP_JWT_SECRET_KEY`。

## 上传自己的政策

1. 使用管理员账号登录；
2. 打开「政策知识库」；
3. 点击「上传政策」，选择 PDF、DOCX、Markdown 或 TXT；
4. 等待系统解析文件并建立版本草稿；
5. 检查条款、页码和版本信息后发布；
6. 返回对话页，用自己的说法提问。

也可以先上传 [`examples/虚构政策示例.md`](examples/虚构政策示例.md)，体验从入库到引用回答的完整过程。

## 技术栈

- Frontend：React 19、TypeScript、Vite、React Flow
- Backend：FastAPI、Pydantic、Python 3.11+
- Agent Runtime：LangGraph、PostgreSQL Saver、Capability Registry、自研任务规划与 Harness
- RAG：百炼 Embedding、混合检索、动态 Top-K、Rerank、Query Rewrite、版本与证据治理
- Artifacts：python-docx、openpyxl、PyMuPDF、Pillow
- Channels：Web、飞书机器人（可选）

更完整的模块和状态流转说明见 [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md)。

## 数据与使用边界

仓库以空知识库发布，不包含真实政策、简历、历史会话、运行数据库或服务密钥。使用者上传的资料保存在自己的运行环境中。详细说明见 [`docs/PRIVACY.md`](docs/PRIVACY.md) 和 [`SECURITY.md`](SECURITY.md)。

UniHR 当前是一套可运行的产品 Demo 和 AI 产品工程样例。招聘结果用于辅助人工复核，正式政策口径仍由具备权限的人员确认。
