# 历史工程评测记录

保留自 2026-10-11 的作品说明，供核对历史实验口径。这里记录的是当时的固定测试集与案例，不代表当前线上版本的最新状态。

## Agent EVO：一个保留真实失败的案例

合成对话中，用户把病程“两周”更正为“三天”，并请求总结。第二轮 Agent 重复了首轮的“临床信息不足”模板，没有体现对更正与任务的响应。

我把“同一会话关联”“完整回答保存”“语义更正响应”“关键安全复核”分开评测：前两项可以通过，语义更正仍可失败；模型辅助判定必须保留待人工复核标记。输出重复只是观察，不能单独证明是路由或上下文传递的根因。

验证方案是固定两轮输入和版本，核对更正如何进入上下文及任务路由，针对定位结果调整后新建 run 对照。当前公开案例未展示修复后的受控重跑，因此不宣称该失败已经解决。

## 工程结果的口径

- EVO 2026-10-09 本地主批次：UniHR、Clinical 各 50 条合成用例，100 条完成业务执行并取得 541 次关联模型调用证据；32 条涉及失败断言，40 项关键安全待判断。业务 completed 不代表质量通过。
- 公开 Clinical 主批次为上述批次的 Clinical 子集：50 条、177 次模型调用、17 条含质量失败；另有 2 条独立多轮记录，分开计数。
- Clinical 历史路由对照：同组 100 条合成样本，上下文路由准确率 38%→98%。历史检索对照：同组 20 条固定查询，Mean Precision@5 57%→93%。两者来自不同离线工程集，不能合并为 Agent 总准确率。
- UniHR 的 50 项固定用例是工程测试样本，并非 50 位真实用户。
- 上述证据不构成医生临床有效性验证、真实用户收益或企业规模化部署结论。访客业务版本未提供可核验用量，页面标记为未核验。
