# UniHR · 产品设计

UniHR 面向高校人事和行政经办人员，将政策查询、材料整理和文件制作组织在同一任务中。目标是减少重复搬运信息与核对材料的工作，交付有出处、可编辑、能继续修改的结果。

## 用户任务与范围

经办人负责准备材料和核对业务口径，审核人确认正式用途，制度维护人负责来源版本。当前为个人 Demo，先围绕用户主动提供的材料验证完整任务。

| 用户任务 | 主要负担 | 对应设计 | 验证重点 |
| --- | --- | --- | --- |
| 查制度及适用条件 | 找原文、确认版本与条件 | 回答附来源，条件不清时列出缺口 | 引用能定位，适用范围准确 |
| 整理业务表格 | 计算、处理重复与缺失 | 确认口径，工具计算，异常单列 | 人数与公式可复算 |
| 准备通知及附件 | 多工具搬运，同一信息反复填写 | 沿用确认结果，核对正文与附件 | 内容一致，文件可编辑 |
| 继续修改已有结果 | 重复解释对象和限制 | 保留材料、版本与修改范围 | 未要求变更的结果保持一致 |

首轮聚焦“培训统计与提醒通知”这样的组合任务。更多模板、考勤等系统接入，依据试用中的重复负担决定优先级；正式发送、录用与定薪保留人工责任。

## 从任务到能力的选择

聊天适合起草和解释，Excel 适合计算，Word 适合编辑。工作台将材料、口径、文件和修改要求放在一起，使经办人能接着完成后续工作。

| 任务中的需要 | 使用的能力 | 使用条件 |
| --- | --- | --- |
| 理解自然语言要求、起草通知 | 大模型与任务识别 | 先利用已有材料，只追问影响结果的条件 |
| 核对制度出处与版本 | RAG 政策检索 | 涉及制度解释时使用；单纯统计不额外检索 |
| 统计、读写与检查文件 | 确定性工具与文件校验 | 数字采用计算结果，实际打开交付文件核对 |
| 组合步骤、继续修改 | 任务编排与上下文状态 | 多份材料或工具有依赖时保存中间产物 |
| 沿用常做任务 | 可复用流程（Skill） | 保存步骤和模板，具体人员材料按任务隔离 |

简单文本任务直接处理；复杂任务明确依赖和检查点。增加编排会带来等待和排查成本，优先保证核心任务可用，再扩展流程。

## 核心交付：表格与通知使用同一份结果

[培训跟进案例](cases/training-follow-up.md)定义了具体输入、统计口径、重复和空白处理，以及两份文件的一致性要求。用户先确认会改变结果的歧义，系统再计算、起草、生成并检查。

模型负责理解和文字草拟，计算与文件生成交给工具。页面同时显示汇总、异常、口径和各文件状态；已生成文件可以继续编辑，未完成部分有明确入口。

## 异常与接手人

| 情况 | 系统动作与用户看到的内容 | 谁继续处理 |
| --- | --- | --- |
| 关键口径未明确 | 显示会影响结果的问题，暂停相关计算 | 经办人确认 |
| 空白或来源冲突 | 单列未知、展示差异及原始记录 | 经办人核实，必要时请来源负责人确认 |
| 文件生成失败 | 分别显示各文件状态，保留可用部分 | 经办人选择重试或手工完成 |
| 政策依据不足 | 说明缺少的来源与适用条件 | 制度负责人确认正式口径 |
| 正式使用或发送 | 保留待确认状态与最终版本 | 授权人员审核 |

普通且要求清楚的步骤连续处理。人工确认绑定具体口径或版本，AI 的处理建议单独显示。详细要求见[案例异常处理](cases/training-follow-up.md#异常与继续处理)与 [PRD 第 10、11 节](PRD.md#10-异常与兜底)。

## 验收与试用计划

先用可复算样本检查人数、公式、字段、文件内容及连续修改，再请经办人独立完成任务。

| 层面 | 验收方式 |
| --- | --- |
| 功能 | 文件可打开、可编辑；重试保留材料与可用产物 |
| 内容 | 数字可复算，通知与附件一致，引用可定位 |
| 责任与权限 | 未知项可见，正式决策与发送由授权人员确认 |
| 使用体验 | 观察用户卡在哪一步、是否反复解释、失败后能否继续 |

试用记录覆盖准备、系统处理、核对与返工的总时间，以及首次交付采用情况、实质修改和原因。与原人工流程比较后，再判断是否减少工作量。真实频次、用时和返工基线尚待收集；培训样本当前提供预期与验收要求，尚无完整模型交付记录。
