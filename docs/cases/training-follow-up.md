# 核心案例：培训完成情况统计与提醒通知

负责培训跟进的经办人需要根据名单汇总完成情况，再给尚未完成的人准备提醒。UniHR 将统计表、异常清单和通知放在同一任务里，沿用已经确认的人员与统计口径。

本例使用虚构名单，给出可复算的预期结果与验收要求，完整模型运行和文件交付记录尚待补齐。

## 先确认会改变结果的条件

> 请根据培训名单，整理完成情况，计算完成率，并起草一份提醒通知。

重复人员怎么算、空白状态是什么意思、通知发给谁，都会影响结果。系统先检查现有材料，再请经办人确认这些条件。

本例约定：按人员编号统计，每人计一次；空白状态单列待核实；完成率以全体应参训人员为分母；提醒明确未完成的人，截止日期暂未确定。

[示例名单 CSV](../../examples/training-follow-up.csv)有 7 行，E04 重复出现。确认两行是同一人的相同记录后，预期结果如下。

| 核对项 | 预期结果 |
| --- | --- |
| 应参训人数 | 6 人 |
| 已确认完成 | 3 人：E01、E04、E05 |
| 明确未完成 | 2 人：E02、E06 |
| 状态待核实 | 1 人：E03 |
| 按全体应参训人员计算的已确认完成率 | 3 ÷ 6 = 50%，同时显示 1 人待核实 |

通知提醒 E02、E06，E03 留在待核实清单中，截止日期显示待确认。经办人核实未知项、修改文件后，再按单位流程决定是否发送。

## 怎样完成这项工作

经办人提供任务要求、名单和通知用途；涉及培训规定时，再附相关制度。系统在任务中保留确认后的口径、重复记录处理方式、未知项和通知版本。

1. 读取名单，列出重复、空白等异常，确认影响统计的歧义。
2. 用表格工具计算人数和比例，AI 根据结果起草通知。
3. 生成并检查 Excel 与 Word，分别展示文件状态，供经办人下载或继续修改。

界面需要同时呈现汇总、统计口径、异常清单和文件。人数与比例采用工具计算结果；需要解释制度时，再检索原文并显示适用范围。

## 设计取舍

Excel 继续负责计算，Word 用于编辑通知。工作台保留材料、口径和修改要求，让经办人一次说明后拿到两份一致的材料。

本例先做用户上传材料后的统计与通知草拟。考勤系统接入、自动发送及人员考核结论暂不纳入；后续根据重复上传和交接的实际负担决定是否扩展。

## 异常与继续处理

| 情况 | 系统应做什么 | 经办人接下来做什么 |
| --- | --- | --- |
| 同一编号重复且状态一致 | 显示重复原行，等待确认合并口径 | 确认是否同一人 |
| 同一编号状态冲突 | 展示差异，暂停受影响统计 | 核实记录，保留修改说明 |
| 状态空白 | 单列待核实，说明统计中如何处理 | 补充信息或保留未知 |
| 截止日期未确定 | 草稿醒目标记待确认，先完成其余正文 | 确认日期后再用于发送 |
| Excel 成功、Word 失败 | 分别显示结果，保留表格与通知正文 | 重试失败步骤，或复制正文自行完成 |

这些是本例的验收要求，重试是否影响已有文件、格式是否保留，需要在完整运行中检查。

## 验收方法

1. 对照预期检查去重人数、完成率、提醒对象和待核实项，原始名单应保留。
2. 打开 Excel 与 Word，检查可编辑性、公式和字段；通知中的数字与对象应和表格一致，未定日期清晰可见。
3. 只要求修改通知语气时，统计结果与人员范围保持一致。
4. 增加状态冲突、全部空白、缺少人员编号和文件无法读取等情况，检查是否说明失败范围、保留已完成部分并提供继续处理的入口。

## 后续验证

公开项目已有任务工作台、文档与表格工具、文件检查和结果记录。下一步先运行这个完整任务，检查文件与统计，再请经办人试用。

试用记录从接到要求到材料可用的总时间、核对修改次数、重复解释和返工原因，与原人工流程比较。我负责确定这项任务的交付要求、确认点和验收条件，并借助 AI 编程工具实现原型。
