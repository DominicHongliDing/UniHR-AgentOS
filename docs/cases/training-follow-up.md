# 核心案例：培训完成情况统计与提醒通知

本案例展示 UniHR 如何根据培训名单整理完成情况、列出异常记录，并起草提醒通知。设计重点是确认统计口径、处理重复与空白，以及保持表格和通知内容一致。

[返回项目](../../README.md) · [产品设计](../product-design.md) · [完整 PRD](../PRD.md) · [在线示例](https://dominicspace-agent-showcase.peterzhukejie2020.chatgpt.site/apps/unihr/index.html#example)

- 使用者：负责培训跟进的人事或行政经办人。
- 输入：培训名单、统计要求与通知用途。
- 交付：完成情况汇总表、异常清单、可编辑的提醒通知草稿。
- 案例状态：使用虚构材料，提供可复算的预期结果；尚无该样本的完整模型运行记录。

## 关键设计：先确认统计口径

> 请根据培训名单，整理完成情况，计算完成率，并起草一份提醒通知。

这项要求同时涉及统计和通知制作。重复记录的处理、空白状态的含义及提醒对象会改变结果，系统先利用材料识别这些歧义，再请经办人确认。

本例约定：按人员编号统计，每人计一次；空白状态单列待核实；完成率的分母是全体应参训人员；提醒对象为明确未完成的人；截止日期尚未确定。

[示例名单 CSV](../../examples/training-follow-up.csv)有 7 行，E04 重复出现。经办人确认两行是同一人的相同记录后，预期结果如下。

| 核对项 | 预期结果 |
| --- | --- |
| 应参训人数 | 6 人 |
| 已确认完成 | 3 人：E01、E04、E05 |
| 明确未完成 | 2 人：E02、E06 |
| 状态待核实 | 1 人：E03 |
| 按全体应参训人员计算的已确认完成率 | 3 ÷ 6 = 50%，同时显示 1 人待核实 |

通知仅提醒 E02、E06，E03 进入待核实清单；截止日期显示待确认。经办人可以核实未知项、修改文件，再按单位流程决定是否发送。

## 功能与页面行为

| 环节 | 设计要求 |
| --- | --- |
| 用户输入 | 任务原话、名单、通知用途；涉及制度时附相关资料 |
| 当前任务信息 | 已确认的统计口径、人员编号、重复处理方式、未知项与通知版本 |
| 处理步骤 | 读表并列异常 → 确认歧义 → 计算与复核 → 起草通知 → 生成并检查文件 |
| 模型输出 | 任务说明、待确认问题、通知草稿；人数与比例引用工具结果 |
| 页面展示 | 汇总、口径、异常和可编辑文件；每份文件分别显示状态，支持继续修改 |

AI 负责理解表达、衔接材料和起草文字，工具负责计算、读写与检查文件。需要解释培训规定时再检索政策，并展示原文和适用范围。

## 范围与取舍

这个任务优先保证一次说明后得到两份一致的材料。Excel 的计算和 Word 的编辑能力继续沿用，工作台负责保留口径、来源和修改要求。

本案例范围包括用户上传材料、统计和通知草拟；考勤系统接入、自动发送及人员考核结论暂不纳入。后续依据重复上传和交接的实际负担，决定是否增加系统连接。

## 异常与继续处理

| 情况 | 系统应做什么 | 经办人接下来做什么 |
| --- | --- | --- |
| 同一编号重复且状态一致 | 显示重复原行，等待确认合并口径 | 确认是否同一人 |
| 同一编号状态冲突 | 展示差异，暂停受影响统计 | 核实记录，保留修改说明 |
| 状态空白 | 单列待核实，显示其对统计解释的影响 | 补充信息或保留未知 |
| 截止日期未确定 | 草稿醒目标记待确认，先完成其余正文 | 确认日期后再用于发送 |
| Excel 成功、Word 失败 | 分别显示结果，保留表格与通知正文 | 重试失败步骤，或复制正文自行完成 |

上述为验收要求。文件重试的影响范围、格式保留和失败恢复，需要在完整运行中逐项检查。

## 验收方法

1. 对照预期核查去重人数、完成率、提醒对象与待核实项，保留原始名单。
2. 实际打开 Excel 与 Word，检查可编辑性、公式和字段；通知中的数字和对象应与表格一致，未定日期清晰可见。
3. 仅修改通知语气，核查统计结果与人员范围是否保持一致。
4. 增加状态冲突、全部空白、缺少人员编号和无法读取文件等反例，检查失败范围、已完成部分与后续入口。

经办人试用时记录从接到要求到材料可用的总时间、核对修改次数、重复解释和实质返工原因，再与原人工流程比较。
