# 一份培训完成情况表，怎样才算做完

[返回项目](../../README.md) · [产品设计](../product-design.md) · [完整 PRD](../PRD.md) · [看三步示例](https://dominicspace-agent-showcase.peterzhukejie2020.chatgpt.site/apps/unihr/index.html#example)

## 从经办人的工作开始

培训结束后，经办人要汇总完成情况，核对名单，再给尚未完成的人准备提醒。表格和通知用的是同一批信息，但经常要分别处理：先确认统计口径，在 Excel 中算结果，再把相关内容整理进 Word，最后检查两份材料是否一致。

UniHR 的场景来自我的人事与行政工作。这里用一份虚构名单展开设计，附上可以手工复算的材料；它是产品需求示例，尚未记录这份样本经模型处理后的实际交付结果。

> 请根据培训名单，整理完成情况，计算完成率，并起草一份提醒通知。

“完成率”还不足以直接开始计算。重复记录怎么算，空白代表什么，通知发给谁，都可能改变结果。产品应先利用现有材料，只追问影响统计和发送对象的条件。

## 先把交付要求说清楚

本例假设经办人确认：按人员编号统计，每人计一次；空白状态单列待核实；完成率的分母是全体应参训人员；提醒通知先给明确未完成的人，截止日期尚未确定。

[示例名单 CSV](../../examples/training-follow-up.csv)有 7 行记录，其中 E04 重复出现。经办人确认这两行是同一人的相同记录后，得到以下结果：

| 核对项 | 预期结果 |
|---|---|
| 应参训人数 | 6 人 |
| 已确认完成 | 3 人：E01、E04、E05 |
| 明确未完成 | 2 人：E02、E06 |
| 状态待核实 | 1 人：E03 |
| 按全体应参训人员计算的已确认完成率 | 3 ÷ 6 = 50%，同时显示 1 人待核实 |

最终交付包括汇总表、异常清单和提醒通知草稿。通知不编造截止日期；E03 不被直接写入“未完成”名单。经办人可以修改文件，核实未知项，再按单位流程决定是否发送。

## 为什么把这些工作放在一个任务里

Excel 已经很适合统计，Word 也适合编辑通知。这里需要 AI 帮忙的部分，是理解经办人的表达，把材料、口径和交付要求接起来，并起草合适的文字；计算和文件读写交给工具完成。

因此，本例先保证“一次说明、两份一致的材料”。不接入考勤系统，不自动发送提醒，也不从这个名单推导人员考核结论。只有反复使用中确认上传和交接确实是主要负担，才值得继续做系统连接。

## 一项功能怎样写清楚

| 环节 | 本例的设计要求 |
|---|---|
| 用户输入 | 任务原话、名单、通知用途；有制度依据时附相应资料 |
| 当前任务信息 | 已确认的人员编号、统计口径、重复处理方式、未知项和通知版本 |
| 处理步骤 | 读表并列出异常 → 确认歧义 → 计算并复核 → 起草通知 → 生成与检查文件 |
| AI 输出 | 任务说明、需要确认的问题、通知正文和待核实项；人数与比例使用工具计算结果 |
| 用户看到的内容 | 汇总、统计口径、重复与空白提示、可编辑文件及各自检查状态；能继续修改 |

检索只在需要解释培训规定时使用。单纯按已确认名单统计，不额外检索一批政策来增加步骤。引用了规定，就需要让经办人找到原文与适用范围。

## 出现问题时怎么继续

| 情况 | 产品应怎样处理 | 经办人接下来做什么 |
|---|---|---|
| 人员编号重复，状态一致 | 显示重复记录，确认合并口径后统计 | 确认是否同一人 |
| 同一编号的状态冲突 | 列出原行，暂停受影响统计，不擅自选择其中一个 | 核实记录，保留修改说明 |
| 状态空白 | 单列待核实，显示其对统计解释的影响 | 补充信息或保留未知 |
| 通知日期未确定 | 草稿醒目标记待确认，仍可先写其余正文 | 确认日期后再用于发送 |
| Excel 成功、Word 失败 | 分别显示结果，保留可用表格和正文 | 重试文件步骤，或复制正文自行完成 |

这张表描述验收要求。重试是否只影响失败文件、不同格式能否完整保留，需要在具体运行中检查，不能由一个下载按钮推定全部满足。

## 怎样验收，而不是只看回答顺不顺

先检查人数、比例和名单是否与上表一致，再实际打开文件。Excel 应保留统计依据和异常；Word 的人数、对象与 Excel 一致，未定日期可见。用户只要求改通知语气时，不应重新改变统计结果。

还要准备状态冲突、全部空白、缺少人员编号、文件无法读取等反例。失败时应说明已处理范围和下一步，不展示虚假的完成状态。

后续请经办人试用时，记录从接到任务到材料可用的总时间、核对修改的次数，以及哪些问题需要重新解释。将这些记录与原来的人工流程比较，才能判断这段设计是否减少了工作量。
